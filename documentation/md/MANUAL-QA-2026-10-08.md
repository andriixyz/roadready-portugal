# RoadReady manual QA — 7–8 October 2026

Manual browser testing of the current working tree, based on commit `b34d6e1`. Application source and existing local changes were preserved. This dated report records the manual pass. Open findings, reproduction steps and acceptance checks are maintained in [QA-HANDOFF.md](QA-HANDOFF.md).

The completed flows produced the expected scores, retained checked answers, and preserved progress on rejected imports. Four findings were reproduced: two P2 issues affecting narrow results and Russian startup fallback, plus two minor presentation issues. Testing continued on 8 October with native Safari, local fault injection and a mocked two-device sync server. Remaining verification limits are listed below.

## Test environment

- Codex in-app browser at desktop viewport 1280 × 720, plus native Safari for clipboard, printing, downloads, navigation and resumed interactions.
- Temporary app copy: `/private/tmp/roadready-manual-20261007`, served at `http://127.0.0.1:42913`.
- Only the temporary copy's Supabase configuration was cleared. Synthetic progress and backups were used. The production origin and the user's actual profile were not used.
- The browser's viewport override did not change `innerWidth`, so responsive checks used an iframe harness with an actual 375- or 320-pixel browsing context. Heights were 812 pixels for the first mock and 640 pixels for subsequent narrow checks. These are responsive layout tests, not physical-device tests.
- Temporary fault-injection app: `http://127.0.0.1:42915/qa/`, with scenario-specific failures and allowlisted synthetic startup profiles. Its cloud configuration is disabled.
- Separate local mock sync app/server: `http://127.0.0.1:42914`. Two-device merge, offline recovery, revision conflict, delayed writes and stale-device reset were exercised against local RPCs that never contact the live Supabase project.

## Reproduced findings

| Priority | Finding | Reproduction and impact |
| --- | --- | --- |
| P2 | Russian results overflow at 320 pixels | Finish a Russian-interface mock at 320 pixels. The time statistic and right-hand action are clipped, and a horizontal scrollbar appears. The HTML content width is 305 pixels but scroll width is 323; the stats/actions are 239 pixels wide but their contents require 290/288 pixels. `.result-stats` uses intrinsic `1fr` tracks and `.result-actions` does not wrap at `styles.css:418` and `styles.css:423`. [Screenshot](../qa/2026-10-08/mobile-result-preview.jpg). |
| P2 | Failed Russian overlay hides the available full bank at startup | With a saved Russian preference, return HTTP 503 for the Russian overlay while EN and PT corpora remain available. Startup falls through both full corpora to six samples and displays zero question records, although the saved profile still contains one session. `loadCorpus()` awaits the overlay within each corpus attempt, so its failure discards that successful full-bank load (`app.js:211–227`). Restoring the overlay and reloading recovers 2/3,910 seen questions and six attempts without reimport: progress is retained, but unavailable while the fallback samples are displayed. [Failure](../qa/2026-10-08/ru-startup-falls-to-samples.png), [recovery](../qa/2026-10-08/ru-bank-restored.png). |
| P3 | Plan counters use incorrect singular forms | With one checked answer, the English dashboard shows “1 answers today” and “1 questions still have a wrong latest answer.” Russian shows “Последний ответ ещё неверный в 1 вопросах.” The displayed numeric values are correct. Relevant strings: `i18n.js` lines 138, 172 and the Russian mistake-evidence counterpart. |
| P3 | An expired target retains the “Exam day” phase label | Import the synthetic expired plan with target 6 October, on 7 October. The main heading correctly says “Update your exam date,” but the phase remains “DAY 20 OF 20 · EXAM DAY.” The phase in `exam-plan.js:82` groups all `daysLeft <= 0` together. |

## Remaining verification limits

- Native Safari reload, Back and sidebar leave warnings were checked. Closing an active quiz tab was not separately exercised. Browser offline mode and a private-key change during an in-flight request were not exercised.
- Physical phones, Firefox compatibility, live production sync/database permissions and RLS, and manual verification of all 3,910 translations, answer keys and legal rules were not covered. Safari results apply to the flows exercised above, not every Safari feature.
- Downloaded CSV content could not be read because OS access was blocked. ChatGPT manual paste and submission were not performed; blank-composer/fallback behavior was observed.
- The public UI returns skipped questions to the unanswered queue; a partial mock submission was not reachable, so unanswered scoring was not manually exercised.
- QA fixture/source checks supported the manual observations. The full release suite and production build were not run; no application-code fixes, commit, push or deployment were performed.
- The two responsive-harness MutationObserver errors remain unattributed.
